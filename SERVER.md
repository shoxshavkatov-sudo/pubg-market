# Сервер: чат, общие объявления, сделки

Сервер (`server/index.js`) на Node.js, **без внешних зависимостей**. Он делает три вещи:
1. раздаёт сайт (папка `public`) и лендинг `/landing/`;
2. даёт **общие объявления**: то, что публикует один человек, видят все;
3. даёт **чат и сделки в реальном времени** между двумя людьми (сообщения, «печатает…», «в сети», шаги сделки).

Сайт и сервер работают с одного адреса, поэтому `public/config.js` настраивать не нужно.

## Как это работает для людей
- В ленте видны объявления всех пользователей.
- Чат появляется только после действия: «Написать продавцу», «Предложить цену» или «Купить через гарант». У продавца чат появляется, когда покупатель ему написал.
- Если собеседник офлайн, сообщения и шаги сделки ждут его на сервере и приходят при следующем входе.
- Сделка (6 шагов) общая: обе стороны видят одно и то же состояние и делают свои шаги (цена, оплата, отвязка, смена почты и номера, подтверждение, выплата).

## Защита через Telegram (рекомендуется для публичного запуска)
В Render откройте сервис → **Environment** → добавьте `BOT_TOKEN` (токен от @BotFather) → сохраните.
После этого сервер принимает только пользователей с проверенной подписью Telegram: имя берётся из Telegram, подделать чужое нельзя.
Обычные браузеры без Telegram при включённой защите на сервер не попадут. Для открытого теста в браузерах оставьте `BOT_TOKEN` пустым.

## Запуск на своём компьютере
```bash
node server/index.js        # нужен Node.js 18 или новее
# сайт: http://localhost:8787
```

## Ограничения (важно знать)
- **Бесплатный тариф Render засыпает** после ~15 минут без запросов. Первое открытие после простоя может идти до минуты.
- **Данные на сервере хранятся в файле на временном диске.** При перезапуске или новом деплое пропадают очередь недоставленных сообщений и объявления на сервере. У пользователей остаются свои копии переписки, а свои объявления приложение отправляет на сервер заново при следующем входе. Для постоянного хранения нужна база данных или платный диск Render (следующий этап).
- Без `BOT_TOKEN` сервер доверяет идентификатору, который присылает приложение.
- Лимиты: до 30 объявлений на человека, до 4 фото на объявление, сообщение до 2000 символов, 240 запросов в минуту с одного адреса.
- **Платежи и баланс тестовые:** деньги в приложении не настоящие, комиссия и выплата считаются только внутри приложения. Для реальных платежей нужен платёжный провайдер и серверная часть кошелька.
- Верификация продавца (почта, телефон, документ) пока отмечается вручную: проверки на сервере нет.

## Справочник API
| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/health` | проверка работы |
| GET | `/api/stream?uid=&name=` | поток событий (SSE): сообщения `m`, шаги сделки `deal`, «печатает» `ty` |
| POST | `/api/send` | отправить сообщение `{to, text, id, ctx, rp}` |
| POST | `/api/deal` | отправить состояние сделки `{to, deal}` |
| POST | `/api/ack` | подтвердить получение `{ids}` |
| POST | `/api/typing` | «печатает…» `{to}` |
| GET | `/api/presence?uid=` | в сети ли пользователь |
| GET | `/api/listings` | все объявления |
| PUT | `/api/listings/mine` | заменить свои объявления `{items}` |
